# spring-testing：中文使用指南

本指南是针对当前收录内容的中文整理，英文上游和许可证保留在 `upstream/`。未列出的方法仍需查对应版本源码和文档。

## 什么时候使用

需要验证 Spring 业务或配置行为时使用。先遵守项目测试规则，按变更和风险选择单测、切片或集成测试，不因上游示例自动升级测试依赖。

| 方法或能力 | 中文用途和场景 | 优先选择与边界 |
| --- | --- | --- |
| JUnit `@Test` | 执行可重复的单元测试 | 优先验证公开行为和边界，不把实现细节当契约。 |
| AssertJ `assertThat` | 对返回值或状态做可读断言 | 断言业务关键值；不要只验证测试代码自身。 |
| AssertJ `assertThatThrownBy` | 验证预期异常和必要信息 | 同时检查异常类型与业务错误契约；不要捕获后吞掉。 |
| Mockito `given` / `willReturn` | 控制依赖在测试中的返回 | 只模拟需要隔离的边界，避免让模拟替代被测逻辑。 |
| `ArgumentCaptor` | 检查传给依赖的关键参数 | 只有参数本身属于需验证的行为时使用。 |
| `@MockitoBean` / `@MockitoSpyBean` | 在支持的 Spring 测试上下文中替换或包装 Bean | 按当前 Spring 版本和项目既有测试写法选择；不要假定每个版本都有。 |
| `@DirtiesContext` | 标记测试上下文需要重建 | 仅在确实污染上下文时用；过度使用会影响测试速度。 |
