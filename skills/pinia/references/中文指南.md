## 什么时候使用

多个组件需要共享、长期维护的客户端状态时查阅。简单组件局部状态优先 Vue `ref`；路由本身承载的筛选条件按现有 URL 方案处理。

| 方法或能力 | 中文用途和场景 | 选择与边界 |
| --- | --- | --- |
| `defineStore` | 声明具有状态、派生值和操作的 store | 先查现有 store；避免为一次读取新建平行 store。 |
| `state` / `ref` | 维护 store 的源状态 | 保持 API 原值及类型，不把大整数 ID 强转为数字。 |
| `getters` / `computed` | 根据已有状态得到派生结果 | 可计算的数据不重复保存；计算逻辑避免副作用。 |
| `actions` | 封装 store 内相关操作 | 请求、权限和错误沿用项目服务层；不绕过已有 API。 |
| `storeToRefs` | 解构需要保持响应性的状态与 getter | 普通解构可能失去响应性；方法使用方式核对其上下文。 |
| 持久化插件 | 按项目约定保存需要持久化的状态 | 先查现有配置与失效策略，不擅自保存凭证或敏感数据。 |
